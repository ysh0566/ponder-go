## Callback RPC methods

The Go starter passes an `*rpc.Client` to `runtime.Handler`. Generated callback registries expose an `*indexing.Client` with event-aware reads. The pinned Ponder callback API lists 21 named actions. All 21 have high-level methods on `indexing.Client`. [Go callback context](../indexing/types.go) · [Upstream action list](https://github.com/ponder-sh/ponder/blob/17c6d5ba0648c1a29bcb74c7d4c56733a4ec5334/packages/core/src/indexing/client.ts#L122-L152)

| Area | Available on `indexing.Client` | Remaining scope |
| --- | --- | --- |
| State and contract reads | `GetBalance`, `GetCode`, `GetStorageAt`, `ReadContract`, `Multicall`, `GetFeeHistory`, `GetProof`. Fee history and EIP-1186 proofs default to the event block. [Backend tests](../parity/runs/native-state-reads/RESULT.md) `Call`, `EstimateGas` and `SimulateContract` support event-relative execution, state overrides, prepared calldata and temporary deployments. [Simulation tests](../parity/runs/native-contract-simulation/RESULT.md) | Transactions use RPC-formatted fields, including any prepared blob fields. |
| Blocks and transactions | `GetBlock`, `GetTransactionCount`, `GetBlockTransactionCount`, `GetTransaction`, `GetTransactionReceipt`, `GetTransactionConfirmations` | All six named methods are present. Transaction, receipt and block objects retain their JSON-RPC field representation. [Transaction tests](../parity/runs/native-transaction-actions/RESULT.md) |
| ENS | `GetEnsName`, `GetEnsResolver`, `GetEnsAddress`, `GetEnsText`, `GetEnsAvatar`. Media records support inline and remote images, IPFS/IPNS, Arweave, ERC-721 and ERC-1155. [Avatar tests](../parity/runs/native-ens-avatar/RESULT.md) Forward resolver discovery and onchain records use the event block and chain deployment metadata. Both address overloads, text keys, gateway arguments, missing records and reorgs are covered on PostgreSQL and PGlite. [Record tests](../parity/runs/native-ens-records/RESULT.md) [Resolver tests](../parity/runs/native-ens-resolver/RESULT.md) | Gateway availability and externally hosted media depend on the endpoint. |

`Request` accepts raw JSON-RPC methods and parameters. Callers supply the block argument for historical reads and implement any higher-level action logic they need. The lower-level `rpc.Client` has its own receipt helper. Native multicall resolves the chain’s Multicall3 deployment at the requested height or accepts an explicit address. A sender or state override applies to the whole aggregate. Per-contract caching applies to aggregates that use the ordinary sender and state. [Multicall verification](../parity/runs/native-multicall-options/RESULT.md) [Raw request handling](../indexing/client_requests.go) · [RPC receipt helpers](../rpc/actions.go) · [Multicall options](../indexing/client_multicall.go)

High-level contract and ENS reads resolve EIP-3668 by verifying the revert sender, retrieving the gateway response and issuing the contract callback. The pinned client uses the selected block for the initial call and latest for the callback. The ENS local batch gateway supports nested requests and Solidity-encoded per-member failures. The raw JSON-RPC method exposes the original node response. [Protocol and backend tests](../parity/runs/native-ccip-read/RESULT.md)

(456 pure, 144 PostgreSQL, 69 PGlite), plus **276 race executions**, for **945
case executions**. It reruns the entire v13 selection of 612 unique leaves on the
new input. Its 57 additional qualified leaves comprise 36 omnichain/receipt
supplements and 21 affected legacy store controls. These are selection counts,
not whole-project completion. See
