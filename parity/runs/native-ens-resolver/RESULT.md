# ENS resolver discovery at the event block

`GetEnsResolver` calls `findResolver(bytes)` on the configured Universal Resolver. It accepts an ENS-normalized name, an optional explicit block or resolver address, and returns the address in the first field of the ABI result. A successful zero address is preserved. Configured chain suffix restrictions and the Universal Resolver deployment height are checked.

A native historical event callback ran on fresh Anvil 1.8.5 chains with PostgreSQL 14.24 and PGlite 0.2.13 business transactions and separate durable callback caches. A local contract returned the address stored at the Keccak hash of the complete call data. The slot written by the test was independently generated by viem for `alice.eth`, so the result depends on the exact function selector, ABI encoding and DNS packet.

The callback for block 1 returned the original resolver after block 2 selected a different address. Explicit height 2 returned the second address. Replacing block 2 with an empty block restored the first address at height 2, while an explicitly immutable cached query retained its earlier answer. An unregistered name returned a zero address and an unsupported suffix was rejected. Wire vectors cover root, leading and trailing dots, UTF-8, and bracketed labelhash encoding for a label exceeding 255 bytes.
