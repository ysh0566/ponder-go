## 数据库

历史同步包的两种模式均通过 115 个顶层测试、605 个叶子用例。覆盖场景包括 12,000 个区块的稀疏日志范围、处理器中途退出、重新打开数据库和恢复索引。两个后端的生命周期测试还验证了排队心跳和租约恢复。运行使用 PostgreSQL 14.24、PGlite 0.2.13、Go 1.25.11 和 Foundry 1.8.5。[数据库格式和重开约定](../current-database-formats/RESULT.md)

## 验证流程

普通模式和竞态模式各自使用独立的测试数据库。两次运行开始和结束时，1,480 个原生输入文件的指纹均为 `dd1a8e13c7b7653aef144a58dc449b9dc3fa3600a2f08a745b14d980aa083f6f`。普通模式由 `sh tools/verify.sh` 调用，独立竞态运行使用同一版本的 `node tools/go-tests.mjs --race`。两者都以零状态结束。原脚本随后启动了重复的竞态进程，在独立竞态运行成功后将它终止，外层脚本退出码为 137。五个结果汇总程序随后读取两份完整日志，全部成功。结果文件分别保留了脚本状态及各项独立检查的退出码。[逐包结果与日志摘要](results.json)

`go vet ./...`、两个可执行文件构建、SDK、上游子集及差分检查均通过。验证工具有 503 条 Node 测试和 40 条 Python 测试通过。使用当前运行的原始报告时，汇总程序核验两个后端的证据，归档报告保留独立的运行标识。只提供一个后端或放入过期报告的对照检查均触发预期错误。干净检出可重新生成历史同步观察器的对照报告，新生成的报告与归档内容逐字节一致。

区间缓存的三组 TypeScript 编译分别得到 0、6、0 条诊断。6 条预期错误对应四条源码用例。汇总程序同时核对原始位置、两种 Go 模式中的类型检查和两个数据库后端的执行结果。移除编译报告后，四条用例全部失去通过标记。
