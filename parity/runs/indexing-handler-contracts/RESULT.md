# 索引回调和事件类型

PostgreSQL 和 PGlite 各通过上游两个完整文件中的 31 条用例。本阶段为其中 4 条补齐 Go 编译与运行验证，涉及 7 项运行时断言。TypeScript 在解除原抑制的 4 行均报告 TS2339。两处回调只能作为函数调用，另外两处需要先区分事件种类才能访问 `transaction` 和 `args`。

Go 的宽类型包含事件 ID 和区块。缩小到具体事件类型后，调用方可使用该类型的字段。索引服务经同一入口取得注册函数。普通和竞态模式都编译并运行外部正例，检查 4 个编译反例的诊断，并在两种数据库上重放每个用例。

对缓存用例额外观察了上游在 Anvil 上实际部署并铸造的 ERC-20 日志。Go 用原 ABI 和日志重新解码，逐项对照修改前后的事件，执行原始写入、刷新、预取和成员查询。原用例的计数为 0，完整缓存对目标键在修改前后都返回 true。缓存不完整时根据历史访问信息预取的能力由另行执行的回归覆盖。
