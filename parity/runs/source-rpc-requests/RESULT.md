# 来源 RPC 请求验证

固定的 Ponder 0.18.2 原始套件中，RPC 请求和 HTTP 响应体超时两个文件共 9 条用例。原版直接在仅有回环网络的容器中执行，Go 端也在本地 Anvil 1.8.5 上执行了对应请求。普通、限流和空区块用例读取真实区块，只有原用例指定的第一次响应由测试注入。限流回归发出 10 组各 20 次请求，每组之间推进一秒，确认端点上限从 20 增至 21，再注入一次 429 并验证恢复。

| 检查范围 | 普通模式 | 竞态模式 |
| --- | ---: | ---: |
| 完整 RPC 包 | 229 | 229 |
| 完整过滤器包 | 935 | 935 |
| 完整配置包 | 77 | 77 |
| 运行时的最终性、历史日志与同步进度回归 | 14 | 14 |

表中数字为通过的 Go 叶级用例，两种模式均无失败或跳过。运行时最终性检查分别连接 PostgreSQL 14.24 和真实 PGlite。每次完整配置包运行还执行了原版配置文件的 40 条用例，结果均为 39 条通过、1 条原始跳过。整个 Go 模块通过编译和静态检查。

异步同步进度新增一条回归测试，同一请求先收到 HTTP 429，再收到空区块。旧提交会在 RPC 层用完重试后再次进入上层重试。修订后的客户端只发出配置允许的两次尝试，并返回包含请求区块号的错误。其他补充测试覆盖同步与异步共享配额、等待取消、按哈希查空区块、固定日志区间和超大区间错误分类。
