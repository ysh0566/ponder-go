# 数据库写入租约和崩溃恢复

PostgreSQL 和 PGlite 在旧实现上都复现了两种错误。先排队的心跳可以覆盖较新的心跳时间，等待期间过期的心跳可以恢复写入权限。修复后，首次取得租约、续租、写入和接管使用数据库时钟。续租在锁定元数据行后检查所有者和到期时间。

| 验证范围 | 结果 |
| --- | --- |
| 旧实现上的排队续租回归 | 两个数据库各复现 2 个错误 |
| 修复后的存储测试 | 普通与竞态模式各通过 67 个叶用例 |
| PGlite 恢复提交后退出 | 修复前独立竞态重跑 3 次中失败 1 次，修复后连续 5 次通过 |
| 上游数据库生命周期的 18 条声明 | PostgreSQL 14.24 和 PGlite 0.2.13 各通过 18 条 |
| Go 模块构建和静态分析 | 通过 |

创建崩溃测试数据时使用生产默认租约。子进程仍在事务提交前后真实退出，接管仍使用 250 毫秒超时并核对持久化状态。旧提交的全量竞态运行曾在创建数据阶段报租约超时。本次新提交验证覆盖了上述存储测试。[命令、用例和原始输出摘要](results.json)
