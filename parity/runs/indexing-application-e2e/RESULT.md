# 应用启动与端到端索引

本地 Anvil 运行固定上游的 ERC‑20、Factory 和 Pair 合约。Go 应用完成初次同步后提供 HTTP 服务。测试通过原版 TypeScript 客户端和原版 Drizzle 表定义读取结果。铸币后零地址余额为 −10¹⁸，接收方余额为 10¹⁸。工厂创建交易对后，两次兑换分别在第 3、4 个区块被索引。两条记录的事件 ID 不同，首条记录的交易对、发送方与接收方均与链上事件一致。

原版两条端到端用例及两条启动命名空间用例在 PostgreSQL 和 PGlite 上各通过 4 条。Go 端使用独立的本地端口及应用命名空间，直接比较部署字节码、ABI、SDK 和表定义的来源。原生 CLI 对两个保留名称分别检查索引和视图命名空间，在编译应用前返回原版错误。补充测试还验证了命令行参数优先于环境变量，以及关闭服务时会等待正在执行的处理函数。修正前，CLI 取消会杀死子进程，使其无法完成关闭。修正后子进程实际收到中断信号，写入关闭标记并正常退出。

复现端到端测试时，将 `PONDER_UPSTREAM` 指向固定版本的上游检出，安装其锁定依赖，在 core 包执行 `wagmi generate` 以生成合约产物。用 Foundry 1.8.5、Node 24 和临时 PostgreSQL 数据库运行 Go 测试，数据库连接通过 `PONDER_TEST_POSTGRES` 传入。PGlite 使用独立的内存库。
